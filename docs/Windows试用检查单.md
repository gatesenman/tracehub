# Windows 试用检查单（TraceHub 1.2.7）

请使用 `TraceHub-1.2.7-setup.exe` 或 `TraceHub-1.2.7-portable.exe`，扩展版本应为 **1.2.7**。下面仍保留此前的扩展验收步骤，供可选增强路径使用。

## 1.2.7 新增：会话文件快照（无需扩展）

- 在「页签快照」页点击「从会话文件读取页签（无需扩展）」，选择一个 **测试用** Chrome 或 Edge 配置，先预览再保存。不要对正在填写表单的日常配置做关闭试验；本路径本来也不能按页签关闭。
- 预览应显示文件时间；若提示旧档或锁定，不要把它当成此刻页签条。若提示读失败，空列表不得被当成成功。
- 保存后用「按窗口重新打开网址」检查是否按窗口打开了 http(s) 网址。不能期待分组、固定或登录态被恢复。
- 该快照上的「关闭这些页签」应不可用。应用不应结束浏览器来读取文件。
- 本项此前只在 Linux 上用合成夹具和假文件系统测过，**Windows / 真实 Chrome 会话文件读取属于首次实机验收**。

# Windows 试用检查单（TraceHub 1.2.2）

本清单用于在 **Windows 真机** 上验收 1.2.2 加固测试版。这不是功能已全部成熟的声明。Linux 交叉打包只核验了 PE 文件格式与资源布局，此前 **从未在 Windows 上运行过本应用**。

请使用 `TraceHub-1.2.2-setup.exe` 或 `TraceHub-1.2.2-portable.exe`。不要安装或运行旧的 1.2.1 产物。扩展必须是本版自带的 1.2.2（安装目录 `resources/extension`，或源码包里的 `extension/`）。

配对令牌、AI 密钥和其他秘密 **禁止** 写入聊天、邮件、截图说明或工单正文。需要排障时只保留「已配置 / 未配置」，或把令牌打码。

## 开始前的风险

- 只使用 **没有未保存表单** 的示例页面（推荐 `https://example.com` 与 `https://example.org`）。不要在工作邮箱、网银、正在填写的表单页上试验保存或关闭。
- 扩展关闭页签走的是 `chrome.tabs.remove`，**可能绕过** 浏览器的 `beforeunload`（「确定离开此页？」）。应用里虽然要求勾选风险确认，仍不能保证表单内容可恢复。
- 恢复应通过已配对扩展在 **同一个浏览器配置** 里打开。不要指望系统默认浏览器；也不要在未配对时强制恢复。
- 建议使用隔离的 Chrome / Edge 配置文件（或全新测试用户），避免碰到日常页签。
- 首次真实 GUI 曾出现保存失败与按组恢复失败。保存已在 Linux GUI 复验通过；恢复修复只通过了集成测试，**尚未在真实 GUI 复验**。关闭从未在真实 GUI 验证。Windows 上这些步骤都属于首次实机验收。

## 步骤

1. **安装或解压**
   - 安装包：运行 `TraceHub-1.2.2-setup.exe`，可改安装目录，按向导完成。
   - 便携包：运行 `TraceHub-1.2.2-portable.exe`（无需安装）。
   - 启动后应看到应用窗口。若闪退，记录用户目录下的日志（见文末），不要继续改系统文件。

2. **完成引导（若出现）**
   - 按提示完成同意/引导。本轮试验 **不要打开真实历史同步**（保持配置文件未启用，或先只做页签快照）。
   - 缩略图、正文抓取等网络增强保持默认关闭即可。

3. **加载扩展**
   - Chrome 或 Edge：打开扩展管理，开启「开发者模式」，选择「加载已解压的扩展程序」。
   - 路径优先用安装目录下的 `resources/extension`；便携包则在对应解压/资源目录中找同名文件夹；也可以用源码包里的 `extension/`。
   - 确认扩展版本为 **1.2.2**。若仍是 1.2.1 或更早，停下来换本版扩展。

4. **配对（不要泄露令牌）**
   - 在应用设置中查看本机桥地址（仅 `127.0.0.1`）并复制配对令牌。
   - 打开扩展选项页，粘贴保存。确认扩展显示已配对 / 桥可用。
   - 此后截图或记录问题时，令牌必须打码或删除。

5. **只打开无表单示例页**
   - 在 **已加载扩展的同一个浏览器配置** 中打开 `https://example.com` 和 `https://example.org`。
   - 不要打开未保存表单、登录页或日常工作页。可为这两个页签建一个测试分组，便于后面做「按组恢复」。

6. **保存快照**
   - 点击扩展 popup 的保存。应用工作区应出现这两个页签。
   - 若失败：记下界面报错全文（不要附带令牌）、扩展是否仍为 1.2.2、桥是否已配对。Linux 上曾出现 `api is not a function`，本版已修，若再现须当作回归。

7. **重启应用再读取**
   - 完全退出 TraceHub 后再次打开（不要只刷新页面）。
   - 确认刚才的快照仍在，标题/网址/分组信息还在。这是在验证本地持久化，不是在验证恢复打开。

8. **关闭确认（可选，仍然只用示例页）**
   - 仅当第 6、7 步成功，且当前窗口只有示例页时，才可试用「关闭并快照」。
   - 必须先成功持久化，再勾选未保存表单风险确认，再执行。
   - 观察：应用是否先显示「等待扩展执行」，扩展回执后才变成已关闭或失败；被导航过的页签不应被关掉。
   - 这一步此前 **从未在真实 GUI 验证**，失败是可能的。不要对重要窗口做这一步。

9. **按组恢复**
   - 在快照上选择按组恢复并确认。
   - 预期：由已配对扩展在同一浏览器中打开对应窗口/页签，并尽量恢复固定状态与分组。最大化窗口不应再因为同时带尺寸参数而直接失败。
   - 若显示「恢复失败」，把界面上的错误原文、窗口是否最大化、扩展版本记下。不要把失败改写成成功。这一修复尚未在真实 GUI 复验。

## 失败时收集什么

在反馈中提供：

- 应用版本（应为 1.2.2）、Windows 版本、Chrome 或 Edge 版本、扩展版本。
- 做到检查单的第几步、界面原文（「恢复失败」「扩展打开失败」等）。
- 应用用户数据目录中的日志（安装版一般在 `%APPDATA%\TraceHub` 或产品名相近目录；便携版看启动目录旁的用户数据。具体以实际生成的文件夹为准）。
- 不要包含：配对令牌、API 密钥、Cookie、浏览历史导出全文、其他配置文件里的秘密。发送前请先检查并打码。

本检查单不能代替完整的产品验收，只用于把 1.2.2 测试版在 Windows 上跑通最小闭环：安装 → 加载扩展 → 配对 → 示例页保存 → 重启读取 →（可选）关闭确认 → 按组恢复。
